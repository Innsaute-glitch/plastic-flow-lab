# Plastic Flow Lab

**An AI-assisted simulator for a campus plastic-waste collection and sorting system.** The AI proposes a better setup; the simulation verifies it.

Made for the college assignment *"Plastic Waste Management: From Collection to Recycling"* (bullet 2: set up a collection and sorting system).

> **A note on authorship.** This is not one of my usual hand-written learning projects. The code in this repository was generated by AI ([Claude Code](https://claude.com/claude-code), using several coding agents), and many of the design choices were proposed by the AI as well. My part was writing the brief, answering and approving the design questions, and reviewing and testing the result. Please don't read it as a demonstration of my own coding or design skills.

## What it does

1. **Map your campus.** Place up to 10 waste-generating nodes (canteen, hostels, library...) and a sorting facility on a map screenshot.
2. **Describe today's setup.** For each node set the waste type, kg/day, rush hours, bins (type, count, size) and pickup interval; pick the facility's sorting method.
3. **Run 30 days.** An hourly simulation plays back in about 30 seconds: bins fill, overflow and leak litter, trucks drive the shortest route, and the facility sorts plastic into bales.
4. **See where every kilogram went.** Metrics (recovery, purity, contamination, overflow, distance, cost), a flow diagram from generation to recycling route, and a per-node table.
5. **Optimise with AI.** Claude Sonnet proposes new pickup intervals, bin types and sizes and a sorting method, with a reason for each. The **same simulation re-runs** the proposal and shows before vs after, checked across 5 random seeds and against a cost budget.

On the demo campus the AI's plan takes overflow from **152 bin-days to 0**, litter from **253 kg to 0** and recovery from **18.7% to 41.1%**, for **+20% cost** (budget: +25%). *All numbers are model results from placeholder assumptions until sourced values are added.*

## Quick start

**No terminal experience?** Follow **[GETTING-STARTED.md](GETTING-STARTED.md)**: install Node.js, then double-click `start-windows.bat` (Windows) or `start-mac.command` (Mac). It also explains how to open the app on an Android phone or iPhone over Wi-Fi.

**Developers** (Node.js 20+):

```bash
npm install
npm run dev      # http://localhost:5173 (dev server with the AI endpoint)
npm start        # build + production server at http://localhost:8787
npm test         # 50 automated tests
```

**Demo path (3 minutes):** Load demo → switch **Demo** on → **Run** → read the baseline → **Optimise** → before/after.

### Demo mode vs live AI

- **Demo on:** replays a real saved Claude answer for the demo campus (`public/demo/cached-proposal.json`). No internet or login needed. If the scenario has been edited, it falls back to the built-in rule-based plan.
- **Demo off:** calls Claude Sonnet through the server. By default it uses a logged-in [Claude Code](https://claude.com/claude-code) subscription (`claude -p`). To use an API key instead, set `"provider": "anthropic-api"` in `config/llm.json` and put `ANTHROPIC_API_KEY` in `.env` (see `.env.example`). The key never reaches the browser.
- If the AI fails or returns an invalid answer twice, the app uses a labelled rule-based fallback, so Optimise always works.

## How it works (short)

![Architecture](docs/images/architecture.png)

- **The simulation is a pure function:** `simulate(scenario, setup, assumptions, seed) → results`. It runs 720 hourly steps and covers generation with rush hours, bin fill and overflow (40% litter, 60% picked up later as contaminated), and end-of-day pickups (interval *k*: day *d* when `(d+1) mod k = 0`). It also plans the shortest truck routes, and sorts plastic with throughput, accuracy and contaminant detection by method. Same inputs always give identical results.
- **The animation only replays** the simulation's timeline; it never computes outcomes.
- **The AI only proposes settings.** Its answer is validated, out-of-range values are clamped, invalid JSON is retried once, and it falls back to a rule-based plan. The prompt requires the smallest bin that works, cost within budget, and reasons that cite input numbers, never predicted results.
- **All model numbers live in `config/assumptions.json`**, each with a unit, a source and an estimate flag. Costs can be edited in the app's Assumptions panel and are saved with the scenario.

## Plugging in real data

These drop in with **no code changes**:

- **Field data:** fill `data/nodes.template.csv`, then use **Import → CSV** in the app and click each node's spot on the map.
- **Real map:** follow `public/maps/README.md`, or use **Change image** + **Calibrate** in the app.
- **Sourced assumptions:** edit values and sources in `config/assumptions.json` and set `"estimate": false`.

After changing the demo scenario, regenerate the cached AI answer with `node server/cli-optimise.mjs <scenario.json> <baseline-results.json>`.

## Tests

`npm test` runs 50 tests: hand-calculated simulation cases (overflow days, pickup timing, backlog, sorting, cost, routing), mass balance (every kg accounted for), determinism, AI answer clamping, retry and fallback, demo replay and fingerprint, and app, animation and results checks. An independent rebuild of the simulation matched every number.
